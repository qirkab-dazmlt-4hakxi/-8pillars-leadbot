# GOAT Intelligence Fabric

GOAT Intelligence Fabric is the proprietary intelligence and voice
orchestration layer of GOAT OS.

GOAT owns the operating architecture.

Foundation models remain replaceable inference engines.

## GOAT-controlled systems

GOAT controls:

- organizational memory
- conversation state
- specialist agent routing
- model routing
- tool execution
- authorization
- construction-domain context
- evidence provenance
- grounding requirements
- high-risk confirmation
- prompt-injection defenses
- evaluation
- voice session state
- interruption and barge-in
- voice latency telemetry
- cross-platform behavior

## Specialist intelligence

The architecture supports specialist domains for:

- executive intelligence
- estimating
- preconstruction
- concrete
- electrical
- plumbing
- earthwork
- project operations
- procurement
- finance
- CRM
- sales
- marketing
- land intelligence
- security

Specialist outputs can later feed an executive arbitration layer.

## Model independence

GOAT may route intelligence to:

- internally operated models
- private inference servers
- specialized classifiers
- specialized vision models
- optional external model providers

Sensitive data policy determines which models are eligible.

Restricted and financial information can be forced to internally operated
models.

## Optional OpenAI engine

The OpenAI adapter is isolated behind GOAT interfaces.

It provides optional access to:

- model inference
- tool-capable model responses
- audio transcription
- speech generation
- realtime voice

OpenAI credentials remain server-side.

No permanent provider API key belongs in:

- iPhone
- iPad
- Android
- browser clients
- Windows clients
- macOS clients

GOAT business logic does not depend directly on the OpenAI API.

## Organizational memory

Memory is:

- tenant isolated
- integrity hashed
- typed
- importance weighted
- optionally pinned
- optionally expiring

Memory never grants authority.

A remembered statement cannot authorize a financial, security or business
mutation.

## Tool security

GOAT tools define:

- schema
- required capability
- allowed roles
- data classification
- risk level

Read-only, mutating and high-risk operations are distinct.

High-risk operations require explicit authorization and confirmation.

Retrieved documents and external content are data, not authority.

## Grounding

High-assurance answers must preserve evidence.

GOAT must not fabricate:

- dimensions
- quantities
- prices
- engineering requirements
- code requirements
- contract requirements
- schedule facts
- supplier facts
- financial values

Missing evidence remains unresolved.

## Voice architecture

GOAT voice maintains explicit states:

- idle
- listening
- thinking
- speaking
- interrupted
- closed

Barge-in is first-class so a user may interrupt a response naturally.

GOAT measures:

- speech-end to first token
- speech-end to first audio
- total conversational-turn latency

## Cross-platform architecture

The same authoritative intelligence service is designed to support:

- iPhone
- iPad and iPad Pro
- Android
- macOS
- Windows
- web

Clients provide native microphone, speaker, camera, secure local storage
and user interface functionality.

Server-side GOAT remains authoritative for permissions, tools, financial
state and company data.

## Frontier-model boundary

GOAT does not falsely claim to have trained a frontier foundation model
from scratch.

Instead, GOAT owns the proprietary company intelligence architecture around
replaceable models.

This enables increasingly specialized construction, financial, operational,
sales, land, executive and security intelligence while avoiding dependence
on a single inference provider.
